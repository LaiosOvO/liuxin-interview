## Implementation Decisions

### Locked decisions（PRD §18 直接固化，不再讨论）
- 节点名 `auto_archive_to_storage`（snake_case）；title 「自动归档（外部存储）」
- mock 服务端口 5000；docker-compose service 名 `mock-archive-service`；URL 通过 env `ARCHIVE_SERVICE_URL`（默认 `http://mock-archive-service:5000/archive`）
- AutoNode actor 统一字符串 `system:auto`（与 PRD §18.3 一致）
- AutoNode 失败行为：raise HTTPException 等价 → graph.ainvoke 会抛 → action_log.failed + 流程卡住，与人工节点失败补偿对称（NodeService Step 4 路径）
- 节点拓扑变更：在 graph.py 把现有的 `applicant_final_confirm → archive` 边换成 `applicant_final_confirm → auto_archive_to_storage → archive`（即修改 `route_after_applicant` 不变 — 仍返回 ARCHIVE_NODE_NAME，但 ARCHIVE 改为 AUTO_ARCHIVE_TO_STORAGE，然后 auto_archive_to_storage → archive add_edge）。**最小侵入**：把 `route_after_applicant` 的 ARCHIVE 返回改为 AUTO_ARCHIVE_TO_STORAGE，新增 `auto_archive_to_storage → archive` 边。
- 重试策略：tenacity stop_after_attempt(3) + wait_exponential(multiplier=0.5, max=2)；retry on httpx.RequestError + httpx.HTTPStatusError(>=500)
- httpx timeout：connect=2s / read=8s（与 LLM 调用 8s 对齐）

### Claude's Discretion（实现细节）
- AutoNode helper 实现位置：`backend/src/offboarding_flow/services/auto_node_service.py` — 单文件 < 200 行
- AutoNode 双写顺序按 PITFALLS #2 + CONTEXT §3.3 严格遵循：业务事务 commit → 调外部 API → 失败 mark action_log.failed
- HTTP 客户端：每次调用 `async with httpx.AsyncClient(...) as client:`（不维持长连接 — 节点级别调用频率低）
- 幂等性：node_states upsert 由 NodeRepository.upsert 保证；action_logs 是 append-only（重跑会产生新 PENDING 记录，但 LangGraph 节点函数 normally 不会被重跑，除非 interrupt — AutoNode 无 interrupt 所以正常不会重跑；不过 graph.ainvoke 重试可能触发，所以 action_log 重跑容忍）
- mock-archive-service 用 stdlib + FastAPI 不依赖 sqlalchemy / redis；< 30 行；Dockerfile 基于 `python:3.12-slim-bookworm` + `pip install fastapi uvicorn`
- 测试 mock-archive-service：integration 用 pytest fixture 起一个 FastAPI subprocess（端口 15000 防冲突）；E2E 同样

### 与 Phase 4 并行决策
- 本 worktree 仅修改 `auto_archive_to_storage` 相关代码 + mock-archive-service + graph.py 拓扑插入 + CHANGELOG
- **不动 notification_outbox 模型 / 表 / scheduler**（Phase 4 worktree 在做）
- **不动 services/node_service.py** 主链路（避免冲突）— AutoNode 自己一个 service
- docker-compose.yml 改动仅追加 mock-archive-service service 段（不动其他 service）
- 合并冲突预期：CHANGELOG.md（手动 resolve）、graph.py（导入 + 节点注册 + 边追加 — 与 Phase 4 不冲突，因为 Phase 4 不动 graph 拓扑）、docker-compose.yml（追加新 service 段不影响 Phase 4 的 outbox scheduler）

### 失败补偿
- mock 服务 down → httpx 抛 → tenacity 3 次重试都失败 → AutoNode helper 把 action_log mark failed → 节点函数 raise → graph.ainvoke 失败 → 流程卡住（在 auto_archive_to_storage 节点）
- 运维通过 `scripts/recover_from_db.py --flow-id=...` 重启
- 这正是 PRD §18.3 + §15.3 强调的「能不能自动做 ≠ 应不应该」— 失败时**不自动绕过到 archive**

### 节点函数模板（伪代码）
```python
async def auto_archive_to_storage_node(state: OffboardingState) -> dict:
    flow_id = uuid.UUID(state["flow_id"])
    node_results = state.get("node_results", [])

    # 1) upsert node_states (status=done) - 通过 helper service
    # 2) POST http://mock-archive-service:5000/archive with body {flow_id, node_results}
    #    - 用 tenacity 3 次重试
    #    - 失败 → mark action_log.failed + raise
    # 3) 成功 → INSERT action_log (action=SYSTEM, actor=system:auto, status=SUCCESS)
    #    + append flow_instances.context.node_results
    # 4) return {current_action: "advance", node_results: [{name: auto_archive_to_storage, ...}]}
```

### graph.py 拓扑变更示意
```
Before: applicant_final_confirm → archive → END
After:  applicant_final_confirm → auto_archive_to_storage → archive → END
                                          ↑
                                  失败 → 节点 raise → 流程卡住
```

### mock-archive-service 完整代码（10 行）
```python
# mock-archive-service/main.py
import json, pathlib
from fastapi import FastAPI, Request

app = FastAPI(title="mock-archive-service")
DATA_DIR = pathlib.Path("/data/archive")
DATA_DIR.mkdir(parents=True, exist_ok=True)

@app.post("/archive")
async def archive(req: Request):
    body = await req.json()
    flow_id = body.get("flow_id", "unknown")
    path = DATA_DIR / f"{flow_id}.json"
    path.write_text(json.dumps(body, ensure_ascii=False, indent=2))
    return {"archived": True, "path": str(path)}

@app.get("/health")
async def health():
    return {"ok": True}
```

### 演示话术（PRD §18.3 原话 — 写到 CHANGELOG 或 04.5-COMPLETE）
> 看，这里有一个 auto_archive_to_storage 节点，状态直接是 done，actor 是 system:auto
> 这证明本架构同时支持人机交互节点（三态决策）和自动节点（API/Webhook）
> 未来要接 RPA 或者业务系统真实 API，模式完全一致：节点函数里调外部 API，双写业务表
> 但是 — 注意这里我故意没有把 device_return 等节点改成自动节点，因为：
> 1. 设备归还涉及法律责任，必须人工签字
> 2. 财务结算金额变动需要财务 review
> 3. 法务签字本质是法律行为，AI/自动节点无权代签
> 这就回到 §15.3 的 AI 边界声明：能不能自动做 ≠ 应不应该自动做
